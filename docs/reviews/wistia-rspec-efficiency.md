# RSpec efficiency implementation

Base: `2db3f585334e669e5b1466ded9ffadb1e7dff0ec`. Isolated branch: `perf/wistia-rspec-cops`.

All 106 implemented assigned rules were screened: 104 RSpec, two RSpecRails, no registered Minitest or additional RSpec-factory namespace. FactoryBot belongs to the framework review. The [complete inventory](rspec-efficiency/inventory.json), [coverage table](rspec-efficiency/coverage.md) and [original audit](rspec-efficiency/audit.md) retain their baseline source hashes/line numbers. They are audit evidence, not a claim that every rule needed an edit. No rules, configuration, dependencies or safety policies were removed.

The audit's only measured hotspot evidence was a small baseline synthetic description probe. All other performance findings were source-based hypotheses. No production benchmark or production Ruby-parity sign-off was run on this branch; the parent integration owns the same-14,824-file benchmark and exact Ruby reconciliation. Existing integrated proof on 362240f is prior-source evidence, not proof for these changes.

## Cache and safety contracts

Caches live on an immutable SourceFile and are dropped on a new corrected source. Each fact has a distinct wrapper type, avoiding cross-query collisions. Stored nodes are owned byte ranges plus kind, resolved against the caller's tree; no borrowed tree node survives in the cache. Node facts include failed/absent results. Config facts compare the relevant raw option values, including missing versus explicit invalid values, rather than configuration addresses. Initialization occurs outside cache entry locks.

Corrections retain their existing validation and atomic ownership. Correctability/severity/messages/ranges are unchanged; only work that cannot affect diagnostic metadata is delayed without a corrections sink. This does not implement the user-deferred generic autocorrect scheduler and does not claim combined-cop correction parity.

## Validation

Final results are recorded in [the machine-readable evidence](rspec-efficiency/validation.json). The native matrix includes 1,936 pinned Ruby RSpec cases, documented safety differences, disabled-correction controls, exact diagnostics/ranges/metadata, -a/-A bytes, final offenses and idempotence. The helper tests compare fragment and original full-file surrogate decoding for nested interpolation, CRLF, Unicode encoding headers, marker collision text, chained strings and line continuation; other existing original corpora cover heredoc fallbacks.

The additional routed/unfiltered matrix covers 357 sources across 12 cops. It compares serialized diagnostics, exact edits, corrected bytes and a second pass both with and without a correction sink; callback counts are structural measurements, not production speedups. DescribedClass has a dedicated native routing control plus its existing offense/negative fixtures; it is not falsely counted as a new original-Ruby reference case.

The first full run exposed a test-inventory omission (DescribedClass has no rows in the delegated RSpec fixture); its dedicated routing input fixes that test. This was not a source-output discrepancy. The final rerun passed: **1,102 tests, zero failures, one ignored** (79.28 seconds). All seven trusted runtime scripts exited zero with empty stderr.

Trusted existing runtime scenario scripts are replayed separately. They exercise authored correction/safety programs and are not execution of upstream fixture text. Their literal expected correction scenarios complement the fresh exact-byte native reference matrix; they do not represent a new production workload.
