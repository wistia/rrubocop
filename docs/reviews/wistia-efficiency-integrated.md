# Integrated rule efficiency improvements

All 674 registered rules were screened: 447 core/extension, 121 framework/Migration, and 106 RSpec/RSpecRails registrations. Source changes combine the three reviewed branches, including previously queued selector routing. The code checkpoint is `0a46f7d`; later integration commits contain reports only.

The same 14,824-file Wistia manifest on `310b8e42e91232d07210eff6cacc2f2035a01bda` takes **89.408s uncached**, compared with the previous **99.752s** measurement (10.37% lower wall time). User CPU is 692.826s and system CPU 5.883s. The warm result is **0.464s**. The entire uncached JSON equals the prior validated native output, which was reconciled against original Ruby: exactly three offenses, identical metadata, empty stderr. Exit 1 is expected for those offenses. Combined native tests: **1,113 passed, zero failed, one pre-existing ignored**.

The improvements replace repeated class/file/group analysis with bounded caches, reuse configured regexes, use indexed line access and prefix counts, remove eager neighboring-line allocations, narrow cop dispatch, and reduce duplicate AST comparisons. Department reports contain original-reference, correction-byte and runtime controls. No correction-scheduling changes, binary uploads, or rollout changes are included.

Every audit finding has a disposition. Full-file syntax-validation guards remain intact: skipping them would alter observable correctability/safety, and a full-proposal cache could retain O(edits × file size) bytes without proven repeated proposals. Generic opaque AST hashing is deferred because weaker fingerprints cannot replace exact equality; integer enum buckets retain exact comparison. Broad dispatch-plan caching/source-phase fusion, pass-local emission-state redesign and unmeasured forwarding scans need separate profiling/contracts. These are explicit follow-ups, not claims of exhausted optimization opportunities.

The wall-time comparison uses one new uncached run and a previous separately measured baseline, not interleaved repeated trials. `--cache false` disables lint result reuse but does not flush the OS page cache. Warm timing reuses an available result cache. Detailed measurements, invocation and artifact hashes are in `docs/evidence/efficiency-full-corpus.json`; complete raw artifacts are retained under `/tmp/rrubocop-efficiency-full-0a46f7d`.

The final framework before/after audit replay compares 19,149 identical source/config rows across three modes (57,447 results): every raw JSONL result is byte-identical to the frozen baseline, including diagnostic flags, correctability, edits and final states. The unfiltered strict Ruby comparison retains 11,100 differences, including runtime scenarios; these are unchanged by the optimization pass and do not establish universal Ruby parity.
